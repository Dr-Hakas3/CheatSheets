SSHポートフォワーディングは、大きく **ローカルポートフォワーディング（-L）・リモートポートフォワーディング（-R）・ダイナミックポートフォワーディング（-D）** の3種類に分類されます。

※以下の３つの例はすべてKali上で実行する例

## ローカルポートフォワーディングの設定
```bash
ssh -L local_port:remote_host:remote_port user@ssh.example.com
```
- **-L**: ローカルポートフォワーディングを設定します。

## リモートポートフォワーディング
```zsh
ssh -N -R 127.0.0.1:2345:10.4.158.215:5432 kali@192.168.45.236
```

## ダイナミックポートフォワーディングの設定
```bash
ssh -D local_port user@ssh.example.com
```
- **-D**: ダイナミックポートフォワーディングを設定します。

---

## **1. ローカルポートフォワーディング（-L）**

```
ssh -L local_port:remote_host:remote_port user@ssh.example.com
```

**目的：SSH接続元のローカルポートへのアクセスを、SSH接続先を経由して転送する。**

例えば、次の構成を考えます。

![[Pasted image 20261128061454.png]]

|項目|値|
|---|---|
|SSHクライアント|Kali|
|SSHサーバー|192.168.45.236|
|転送先|10.4.158.215|
|転送先ポート|5432|
|ローカル待受ポート|1234|

```
ssh -L 1234:10.4.158.215:5432 kali@192.168.45.236
```

このコマンドを実行すると、Kali側のローカルポート1234で待ち受けます。

その状態でKaliから次のように接続します。

```
nc 127.0.0.1 1234
```

通信の流れは以下のとおりです。

```
Kali（SSHクライアント）
  |
  | 127.0.0.1:1234
  |
  v
SSHトンネル
  |
  v
192.168.45.236（SSHサーバー）
  |
  | 10.4.158.215:5432
  |
  v
10.4.158.215（転送先）
```

ポイントは、**転送先への接続を行うのはSSHサーバー側**ということです。

つまり、Kaliから直接アクセスできない10.4.158.215:5432に対して、SSHサーバーを経由してアクセスできるようになります。

### **よく使うオプション**

```
ssh -N -L 1234:10.4.158.215:5432 kali@192.168.45.236
```

- `-N`：リモートコマンドを実行しない。ポートフォワーディング専用で使用する。
    
- `-L`：ローカルポートフォワーディングを設定する。
    

## **2. リモートポートフォワーディング（-R）**

```
ssh -N -R 127.0.0.1:2345:10.4.158.215:5432 kali@192.168.45.236
```

**目的：SSH接続先のポートへのアクセスを、SSH接続元側のネットワークにあるサービスへ転送する。**

こちらは-Lと反対方向のポートフォワーディングです。

![[Pasted image 20261128061439.png]]

先ほどのコマンドを分解します。

```
ssh -N -R 127.0.0.1:2345:10.4.158.215:5432 kali@192.168.45.236
```

|部分|意味|
|---|---|
|`-R`|リモートポートフォワーディング|
|`127.0.0.1`|SSHサーバー側の待受アドレス|
|`2345`|SSHサーバー側の待受ポート|
|`10.4.158.215`|SSHクライアント側から到達する転送先|
|`5432`|転送先ポート|

通信の流れは以下のとおりです。

```
192.168.45.236（SSHサーバー）
  |
  | 127.0.0.1:2345
  |
  v
SSHトンネル
  |
  v
Kali（SSHクライアント）
  |
  | 10.4.158.215:5432
  |
  v
10.4.158.215（転送先）
```

ここが重要です。

- SSHサーバー側で2345番ポートを待ち受ける。
    
- 2345番ポートへの接続はSSHトンネルを通る。
    
- SSHクライアント側から10.4.158.215:5432へ接続する。
    

つまり、**SSHサーバー側からアクセスできるようにしたいサービスを、SSHクライアント側のネットワークを経由して公開する**仕組みです。

### `127.0.0.1` **の意味**

今回の指定では、

```
-R 127.0.0.1:2345:10.4.158.215:5432
```

SSHサーバー側のループバックアドレスで待ち受けます。

そのため、基本的にSSHサーバー自身からしかアクセスできません。

なお、SSHサーバー側のネットワークにも公開したい場合は、待受アドレスを変更する必要があります。サーバー側の `GatewayPorts` 設定などにも依存します。

## **3. ダイナミックポートフォワーディング（-D）**

```
ssh -D local_port user@ssh.example.com
```

**目的：SOCKSプロキシを作成し、アプリケーションから指定された通信をSSHトンネル経由で転送する。**

ここが-Lや-Rとの大きな違いです。

-Lと-Rは、基本的に転送先のIPアドレスとポート番号を事前に指定します。

一方、-Dは転送先を固定しません。

アプリケーションからのSOCKSリクエストに応じて、接続先を動的に決定します。
![[Pasted image 20261128061358.png]]

例えば、

```
ssh -N -D 1080 kali@192.168.45.236
```

を実行します。

すると、SSHクライアント側の1080番ポートでSOCKSプロキシが待ち受けます。

ブラウザなどのアプリケーションで、以下のように設定します。

|設定項目|値|
|---|---|
|SOCKSホスト|127.0.0.1|
|SOCKSポート|1080|
|SOCKSバージョン|SOCKS5|

その後、ブラウザから例えば以下のサイトにアクセスします。

```
http://10.4.158.215:8080
http://192.168.45.100:80
http://example.com:443
```

通信の流れは次のようになります。

```
Kali（SSHクライアント）
  |
  | アプリケーション
  |
  v
127.0.0.1:1080
（SOCKSプロキシ）
  |
  v
SSHトンネル
  |
  v
192.168.45.236（SSHサーバー）
  |
  +----> 10.4.158.215:8080
  |
  +----> 192.168.45.100:80
  |
  +----> example.com:443
```

転送先を事前に指定する必要がなく、SOCKSプロキシを利用するアプリケーションから任意の宛先を指定できます。

ただし、実際に接続できる宛先はSSHサーバー側から到達可能な範囲に限られます。

# **4. ダイナミックはローカルとリモートに分類される？**

ここが今回の質問のポイントです。

結論として、次のように整理すると理解しやすいです。

|種類|オプション|待受場所|転送先|
|---|---|---|---|
|ローカルポートフォワーディング|`-L`|SSHクライアント側|SSHサーバー側から接続|
|リモートポートフォワーディング|`-R`|SSHサーバー側|SSHクライアント側から接続|
|ダイナミックポートフォワーディング|`-D`|SSHクライアント側|SOCKSリクエストで動的に決定|

**厳密には、OpenSSHの** `-D` **はローカル側でSOCKSプロキシを待ち受ける機能です。**

したがって、通常のSSHコマンドの分類では、

- `-L`：ローカルポートフォワーディング
    
- `-R`：リモートポートフォワーディング
    
- `-D`：ダイナミックポートフォワーディング
    

という3種類が同列です。

「ローカルダイナミック」「リモートダイナミック」という考え方は、SOCKSプロキシをどちら側で待ち受けさせるかという一般的な概念としては理解できますが、OpenSSHの標準的な `-D` オプションにリモート版があるわけではありません。

# **5. 3種類の使い分け**

![[Pasted image 20261128061231.png]]

## **ペネトレーションテストでの使い分け**

例えば、次のようなネットワークを想定します。

```
Kali
  |
  | SSH
  |
踏み台サーバー
  |
  +---- 10.4.158.215:5432（DB）
  |
  +---- 10.4.158.216:80（Web）
  |
  +---- 10.4.158.217:445（SMB）
```

|やりたいこと|使用する方式|
|---|---|
|DBの5432番ポートだけにアクセス|`-L`|
|Kali側のサービスを踏み台側に公開|`-R`|
|DB・Web・SMBなど複数の宛先を探索|`-D`|

特に、内部ネットワークの探索ではダイナミックポートフォワーディングが便利です。

例えば、

```
ssh -N -D 1080 kali@192.168.45.236
```

とした後、ProxychainsなどにSOCKS5プロキシを設定すれば、対応するツールの通信をSSHトンネル経由にできます。

**覚えておくべき本質は3つです。**

- `-L`：自分側で待ち受け、相手側から転送先に接続する。
    
- `-R`：相手側で待ち受け、自分側から転送先に接続する。
    
- `-D`：自分側でSOCKSプロキシを待ち受け、接続先を動的に決める。
    

この3つの違いは、単なる通信方向だけではなく、**待受ポートの位置と転送先の決定方法**にあります。
